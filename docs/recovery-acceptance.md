# T050–T052 recovery acceptance

This checklist governs the user-authorized Sol/High repair and independent
Astra/High acceptance review. A checklist item requires actual evidence;
implementation presence or an agent's completion statement is insufficient.
The original task specifications and scientific protocol remain authoritative.

## Ownership

- Verification agent: source gate, separate wheel smoke, meaningful legacy tests.
- Pilot agent: acquisition, method execution, passage provenance, inventories.
- Reviewer agent: packet selection, annotation storage/interchange, browser UI.
- Orchestrator: preserve existing user data, coordinate contracts, integrate,
  perform browser checks and report exact remaining limitations.
- Independent Astra reviewer: challenge the integrated result against the audit
  and scientific contracts; no self-certification by implementation agents.

## Evidence required

| Area | Acceptance evidence |
| --- | --- |
| User data | Original packet, annotations and source manifest remain unchanged; new corrected packet has a content-derived identity. |
| Source gate | Normal documented fast and full commands pass Ruff format/lint, strict mypy and the 95% coverage floor, importing this checkout. |
| Wheel | Disposable environment imports installed wheel, runs documented offline smoke, and does not change development import identity. |
| Selection | Frozen unbiased sampling frame/bounds, all draws and eligibility reasons, no date/topic enrichment, counterpart grouping, enforced attempts/bytes/time/retry limits, deterministic resume. |
| Real methods | Native-offset Ab3P, Schwartz–Hearst, pinned PLODv2 and configured hybrid actually executed on identical canonical passages, with identities, timings, coverage and failures preserved. |
| Text alignment | Every SF/LF and independent PLOD span slices back exactly; passage identity survives serialization; source mappings are retained or explicitly unresolved. |
| Source comparison | Retained JATS/BioC source artifacts and artifact-derived audits for at least three selected PMC articles, including actual structural losses/mappings. |
| Packet | Explicit agreement/disagreement/zero strata, complete primary-method coverage required for zero, deterministic selection, article cap and arm balance, denominators and shortages. |
| Validation | Reject changed packet IDs, unknown case IDs, invalid or out-of-range spans, mismatched slice text and supplementary-Unicode offset errors. |
| Decisions | Multiple/overlapping/alternative definitions preserved; proposed-pair decisions distinct from missed-definition/passages; revisions traceable. |
| Save and export | Edit, save, navigate, reload, JSON export/import and BioC export/import preserve decisions and provenance; failed saves never silently navigate. |
| Source rendering | Article text is rendered inertly, including strings resembling HTML; no source content executes. |
| Passage clarity | Article title/source/type/section visible; clearly bounded Passage to review; paragraph breaks; surrounding context distinct; short/long highlights labeled. |
| Review flow | Plain question, per-pair Correct/Incorrect/Unsure, text-selection correction/addition, optional Details, Save and next, reviewed/remaining count and resume. |

## Browser acceptance cases

Use a separate test packet/state, never save experimental decisions into the
user's existing annotations. Include a real source passage and fixtures with
supplementary Unicode, repeated abbreviations, multiple definitions, overlapping
alternatives, source markup, no suggestions, a failed-method diagnostic, and
structural context where available. Test keyboard operation and a narrow view.
Restore any temporary viewport override afterward.

If a runtime, service, browser connection or sample eligibility limit prevents
acceptance, state exactly what passed, what did not, and retain the artifacts
needed to resume. Do not call the milestone complete or quietly weaken criteria.
